# ECharts 可视化编辑器

配合 `scripts/filters/echarts-fence.js` 使用的本地编辑器：在浏览器里拖点、改数值，
改动直接回写到源文件。零依赖（不需要 `npm install`）。

## 快速开始

```bash
npm run echart                                 # 空白画布，在浏览器里选文件
npm run echart -- --file "source/_posts/xxx.md"  # 直接打开某篇文章
```

`ec` 是同一命令的短别名。启动后会打印地址并自动打开浏览器。可选参数：

| 参数            | 说明                                                                |
| --------------- | ------------------------------------------------------------------- |
| `--file <路径>` | 目标文件，相对站点根目录；不传则进入空白画布                        |
| `--port <端口>` | 默认 7788；被占用时自动顺延并打印实际端口                           |
| `--no-open`     | 不自动打开浏览器                                                    |
| `--keep-alive`  | 常驻模式：关掉页面也不退出（默认关掉最后一个标签页 3 秒后自动退出） |

关掉浏览器标签页后，页面会通过 `sendBeacon` 通知服务端退出，终端随之回到提示符，不会留下占着
7788 端口的后台进程。刷新页面不会误杀（新页面会立刻补一次心跳）。如果浏览器崩溃、长时间没有
心跳，则以 120 秒为上限兜底退出。

## 工作区：打开文件 / 新建图表

不带 `--file` 启动时是一块空白画布（默认 420px 高、坐标轴 0–10），可以：

1. 在画布上点「+ 新增」加节点、拖位置、改颜色，做出一张图；
2. 点顶栏「打开…」，弹窗里搜索并选择项目文件（勾选「只看含图表」可直接筛出带
   ````echarts 围栏的文章，并显示每篇的围栏数量）：
   - `.md` → 列出文首 / 各级标题之后 / 文末作为**插入位置**，选好后点「插入当前图表」，
     就会在该位置写入一个 ```echarts 围栏并自动切过去编辑
   - `echarts.js` / `*.json` → 直接「打开」编辑已有图表
   ````
3. 打开一篇**没有图表**的文章时同样是空白画布，做完整张图再用「插入当前图表」落地。

插入只改变目标文件的那一处，其余内容不动；插入后该文件成为当前目标，后续改动会自动写回。

## 支持的三种目标

| 格式           | 判定                     | 回写方式                                                  |
| -------------- | ------------------------ | --------------------------------------------------------- |
| JS 脚本        | 含 `const nodes = [...]` | 只重写 nodes 段，未改动的条目逐字保留，其余代码与注释不动 |
| 纯 JSON option | 文件以 `{` 开头          | 重建 `series` 的 data 后整体序列化                        |
| Markdown       | 后缀 `.md`               | 只替换选中的 ```echarts 围栏正文，围栏外内容一字不动      |

一篇 markdown 里有多张图时，顶栏的下拉框会按「序号 · 行号 · 所属标题」列出所有围栏，
切换即加载对应的图表。

节点数据统一从 `series` 里 `type === 'scatter'` 的那条序列取，坐标、名称、颜色、
标签方位都是逐点编辑的；`type === 'line'` 的那条会按节点顺序重建并闭合回起点。

## 编辑操作

- **拖动**：画布上直接拖气泡；拖动已选中的点会整组移动
- **框选**：空白处按住拖出选框多选，`Shift` + 拖为追加；`Shift` + 点单个加/减选
- **对齐 / 分布**：选中后顶部浮出工具条，支持水平对齐（统一 Y）、垂直对齐（统一 X）、
  水平分布、垂直分布（按 X / Y 等间隔排开，端点不动）
- **批量修改**：改颜色、改标签方位、删除
- **微调**：方向键 0.1，`Shift` + 方向键 0.5
- **撤销 / 重做**：`⌘Z` / `⇧⌘Z`
- **参考网格 / 吸附**：网格显示 1 单位格线，吸附把坐标对齐到 0.5
- **快捷键**：`⌘S` 保存、`⌘A` 全选、`Esc` 取消选择

改动默认防抖 350ms 自动写回，状态栏显示同步结果；也可以关掉「自动同步」手动保存。

## 与线上渲染保持一致

编辑器刻意复刻了博客端的渲染环境，避免"编辑时一个样、发布后另一个样"：

- **ECharts 版本**：`vendor/echarts.min.js` 固定为 6.1.0，与 `echarts-fence.js` 里的
  `echarts@6` 一致
- **容器尺寸**：宽度按主题布局算出的正文宽度 786px，高度取 option 的 `height`
  （缺省 420），与 `#article-container .echarts-wrap` 相同
- **颜色改写**：`blogTune()` 与 `echarts-fence.js` 的 `tune()` 保持同步——背景强制
  `transparent`，文字、轴线、雷达图按浅色/深色主题重新着色

顶栏的「按博客渲染」可切到原始 option 对照，「深色」对应博客的深色主题；这两个开关
只影响预览，不会写回文件。

> 注意：因为主题会把 `backgroundColor` 强制改成 `transparent`，option 里自定义的
> 背景色在线上是不生效的。依赖深色背景的配色（例如白色标签）在浅色主题下会看不清。

## 目录结构

```
tools/echart-editor/
├── server.js          # 本地服务：解析源码、回写、静态资源
├── public/
│   ├── index.html     # 界面
│   ├── app.js         # 拖拽 / 框选 / 批量操作 / 同步
│   ├── style.css
│   └── favicon.svg
└── vendor/
    └── echarts.min.js # 与线上同版本，离线可用
```

服务端用 `vm` 执行 JS 格式的源文件取出真实的 `option`；JSON 与 markdown 格式直接
`JSON.parse`。写回采用「临时文件 + rename」的原子写入。

## 已知限制

- JSON 与 markdown 格式保存时会整体重新序列化，首次保存的 diff 会覆盖整个 option
  （之后就是稳定增量）；只有 JS 格式做到了未改动条目逐字保留。
- 编辑器只动 `series` 的数据，标题、图例、坐标轴等样式需直接改源文件。
- 含 `scatter` 序列的图表按节点编辑；雷达图、饼图等自动切到**数据模式**，右侧直接列出
  `series` 里的数值（雷达图按指标顺序排列，鼠标悬停显示指标名）供修改，改完同样自动回写。
